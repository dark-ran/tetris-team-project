# LAN 대전 입력·표시 지연 검증 (Req3 9쪽)

목표는 같은 LAN에서 한 기기의 키 입력부터 상대 모니터에 해당 블록 이동이 처음 보이기까지 200ms 이하인지 확인하는 것이다.

## 현재 자동 검사의 범위

- `./gradlew test --tests tetris.lan.LanLobbyTest`는 루프백 TCP에서 연결, 준비, 모드 동기화, 경기 시작, 재경기와 연결 복구를 확인한다.
- `./gradlew gameplayPerformanceTest`는 한 JVM에서 입력 처리와 메모리 이미지 그리기까지 걸린 시간을 검사한다.
- 경기 중 ‘네트워크 지연’은 핑 왕복 시간이 200ms를 연속 세 번 넘을 때 표시한다. 상대 PC의 입력 처리와 모니터 표시 시점은 측정 범위 밖이다.

## Windows와 macOS 실측 절차

1. 같은 공유기에 연결한 두 컴퓨터에서 같은 버전을 실행한다. 한쪽에서 P2P 대전 → 서버 열기를 누르고 다른 쪽에서 방장의 LAN IP로 접속한다.
2. 양쪽에서 게임 시작을 누른 뒤, 누르는 키와 상대 모니터의 ‘상대’ 보드가 한 영상에 나오도록 카메라를 배치한다. 120fps 이상으로 촬영하고 원본 촬영 프레임률을 기록한다.
3. 좌우 이동 키를 번갈아 한 번씩 누른다. 키가 내려가기 시작한 프레임 A와 상대 보드에서 같은 방향의 이동이 처음 보이는 프레임 B를 기록한다. 자동 낙하와 키 반복 입력은 제외한다.
4. 지연 추정값은 (B − A) × 1000 / 촬영 fps 이다. 240fps에서 48프레임 차이는 200ms다. 경계에서 한 프레임 이내라면 판정을 보류하고 더 높은 프레임률로 다시 측정한다.
5. 방장 입력 → 참가자 화면, 참가자 입력 → 방장 화면을 각각 10회 이상 기록한다. 각 방향의 최대값과 200ms 초과 건수를 함께 남긴다. 키의 물리적 움직임을 시작점으로 삼으므로 키 스위치 작동 시점과 차이가 있을 수 있다.
