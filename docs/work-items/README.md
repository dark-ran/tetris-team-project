# 작업 기록과 이슈 연결

기능별 작업 범위, 완료 기준, 검증 결과와 후속 작업을 보관한다. GitHub Issue 본문을 작성하거나
검토할 때 근거로 사용하고, Issue가 연결되면 해당 문서에 링크를 남긴다.

이 폴더는 작업 기록이다. 파일 수정만으로 GitHub Issue가 생성되거나 상태가 변경되지는 않는다.
클래스를 사용하는 방법과 확장 예시는 [모듈 연결 안내](../contracts/README.md)에 정리한다.

## 작업 목록

| 작업 | 구현 범위 | 현재 상태 |
|---|---|---|
| [보드와 블록](board-and-piece.md) | 보드, 종류별 저장값, 모양·회전, 다음 목록 | 구현·자동 검증 완료, 검토 대기 |
| [게임 엔진](game-engine.md) | 행동 처리, 상태 사본, 고정·삭제·생성, 일시정지·게임오버 | 구현·자동 검증 완료, 검토·모듈 연결 대기 |
| [색각 표현과 창 크기 변경](display-settings.md) | 5개 모드, 독립 패턴, 미리보기, 크기 유지·취소 | 통합 브랜치에서 로컬 구현·검증 완료, 미푸시 |
| [게임오버 이름 입력](game-over-registration.md) | 입력란 비율·글자·배경, 화면 구성 메서드 정리 | 통합 브랜치에서 로컬 구현·검증 완료, 미푸시 |
| [스코어보드 초기화](scoreboard-reset.md) | 저장소·메모리·화면 초기화, 성공·실패 제어 | 통합 브랜치에서 로컬 구현·검증 완료, 미푸시 |
| [게임 낙하 속도](gameplay-speed.md) | 생성·삭제 두 기준, 점수·레벨·타이머 연결 | 통합 브랜치에서 로컬 구현·검증 완료, 미푸시 |

보드·블록과 게임 엔진은 1번 핵심 로직 범위이다. 담당자는 역할로 표시하고, 사람 지정과 일정은 연결된 Issue에서
관리한다.

## 기록하는 내용

| 항목 | 내용 |
|---|---|
| 목적과 범위 | 해결할 기능과 변경할 코드 |
| 요구사항 | 요구사항 문서의 근거와 검증할 동작 |
| 완료 기준 | 코드와 테스트로 확인 가능한 조건 |
| 검증 결과 | 명령, 실행 환경, 결과 또는 보고서 위치 |
| 후속 작업 | 연결할 모듈, 맡는 파트, 확인할 결과 |
| Issue 연결 | 실제 연결한 Issue 링크. 미연결이면 그대로 표시 |

구현 완료, 검토 완료, 모듈 연결 완료는 서로 다른 상태이다. 통합 전인 기능을 전체 게임의 완료로
표시하지 않는다. 설계와 사용 방법은 연결 문서에 두고, 작업 기록에서는 해당 문서를 연결한다.

## 공통 검증 결과

| 항목 | 결과 |
|---|---|
| 검증일 | 2026-10-02 |
| 환경 | macOS 26.6.2 · Temurin Java 21.0.12.1 · Gradle 8.14.4 |
| 전체 명령 | `./gradlew --no-daemon clean build jacocoTestReport` |
| 테스트 | 196개 통과, 실패·오류·건너뛰기 0 |
| 코드 줄 커버리지 | 보드·블록·구현한 엔진 클래스 100% |
| 분기 커버리지 | 분기가 있는 해당 클래스 100% |
| 자동 기준 | 대상 클래스마다 코드 줄 커버리지 70% 이상 |

테스트 수에는 입력 값을 바꾸어 실행한 사례가 각각 포함된다. 커버리지는 명시한 구현 범위의
측정값이다. 인터페이스와 분기 없는 클래스에는 분기 비율을 적용하지 않는다.

보고서는 `build/reports/tests/test/index.html`과 `build/reports/jacoco/test/html/index.html`에서
확인한다. 위 명령으로 다시 생성할 수 있다. 현재 결과는 로컬 자동 검증이며, 운영체제별 실제
게임 플레이와 원격 자동 빌드 결과는 통합 작업에서 별도로 기록한다.
