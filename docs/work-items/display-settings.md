# 색각 표현과 창 크기 변경

관련 논의: [Issue #4](https://github.com/dark-ran/tetris-team-project/issues/4).
작업 브랜치: `integration/pr-7-8-11`.
검증일: 2026-10-08.

## 구현 범위

기존의 구분 문자 체크박스를 이슈에서 합의한 다섯 가지 색각 모드와 별도의 패턴 설정으로 확장했다.
게임 엔진은 종류별 칸 저장값을 그대로 제공하고, 화면의 공통 `PieceStyle`이 팔레트와 패턴을 선택한다.

| 모드 | 표현 | 모드 선택 시 패턴 기본값 |
| --- | --- | --- |
| NORMAL | 기존 일반 팔레트 | 끔 |
| PROTAN | 적색 계열 보정 팔레트 | 켬 |
| DEUTAN | 녹색 계열 보정 팔레트 | 켬 |
| TRITAN | 청황 계열 보정 팔레트 | 켬 |
| MONOCHROME | 서로 다른 회색 명도 | 켬 |

모든 모드에서 사용자가 패턴을 별도로 켜고 끌 수 있다. 저장한 선택은 다시 실행해도 유지한다.
설정 화면은 7종 블록을 즉시 미리 보여 주며, 단색 모드에서는 패턴 사용을 권장한다.
작은 창에서도 미리보기를 조작 키보다 먼저 보여 주고, 나머지 항목은 세로로 스크롤할 수 있다.
저장 결과·오류 메시지와 하단 버튼은 스크롤 영역 밖에 둔다.

| 블록 | 패턴 |
| --- | --- |
| I | 가로선 |
| O | 점 |
| T | 세로선 |
| S | `/` 대각선 |
| Z | `\` 대각선 |
| J | 격자 |
| L | 다이아몬드 |

패턴은 칸 내부에 드문 간격으로 그리며, 블록이 회전해도 화면에서의 방향은 유지한다.
현재 블록·고정된 블록·다음 블록·설정 미리보기는 같은 렌더러를 사용한다.
각 칸의 경계선을 유지하며, 고스트는 속이 빈 점선 윤곽으로 착지 위치를 표시한다.
고스트 계산은 상태 사본을 사용해 엔진을 변경하지 않는다.

## 저장과 연결 규칙

- `GameSettings.colorVisionMode()`와 `piecePatternsEnabled()`가 독립된 값을 제공한다.
- `withColorVisionMode(mode)`는 선택한 모드의 패턴 기본값을 적용한다. 이후 `withPiecePatternsEnabled(value)`로 사용자가 재정의할 수 있다.
- 창 크기와 키 변경은 기존 모드·패턴 선택을 유지한다.
- `SettingsScreen.Values`는 모드·패턴을 함께 전달하고 `AppController`가 저장 후 게임 화면에 적용한다.
- `color.vision.mode`와 `piece.patterns.enabled`를 저장한다. 기존 boolean 생성자·조회 API는 연결 호환성을 위해 유지한다.
- 이전 파일의 `color.blind.mode=true`는 DEUTAN + 패턴 켬으로 읽는다. 새 필드가 있으면 새 필드를 우선한다.
- 잘못된 모드·패턴 값은 기존 저장소의 기본값 복구 정책을 따른다.

팔레트는 화면 표시용 색상표다. 이번 자동 검증은 표현의 일관성·패턴 구별·저장 동작을 검사했다.
이슈의 시안에 사용한 색각 시뮬레이션을 이번 구현 색상표로 다시 실행하거나 사용자 식별성을 평가한 결과는 포함하지 않는다.

## 창 크기 확인

크기 선택 즉시 실제 창을 변경하고, **변경한 창 크기를 유지하시겠습니까?** 확인창을 띄운다.

- **유지**: 창 크기만 즉시 저장한다. 아직 저장하지 않은 색각 모드·패턴·키 편집값을 보존한다.
- **취소**, 확인창 닫기, Esc: 직전 실제 창 크기와 선택값으로 복원하며 파일을 변경하지 않는다.
- 15초 동안 선택하지 않으면 취소 처리한다. 기본 선택도 취소다.
- 유지 후 저장에 실패하면 직전 크기·선택값·저장 설정을 보존하고 오류를 표시한다.
- 기본값 복구로 크기가 달라질 때도 먼저 확인한다. 취소하면 복구 전체를 취소한다.
- 게임에서 설정을 열었을 때는 확인 과정 내내 게임을 멈춘 상태로 유지한다. 보드·현재 블록·위치·다음 목록·점수는 변하지 않는다.

프로그램 시작 시 저장된 크기를 적용하는 경우에는 확인창을 띄우지 않는다.
확인 동작은 `WindowSizeConfirmation`으로 전달할 수 있어 화면 없는 테스트에서도 저장·복원을 검증한다.

## 검증 결과

macOS / Temurin Java 21.0.12.1에서 실행했다.

```sh
./gradlew clean build jacocoTestReport reviewWindowTest
```

| 검사 | 개수 | 실패·오류·건너뛰기 |
| --- | --- | --- |
| 일반 테스트 | 299 | 0 |
| 실제 모듈 통합 테스트 | 1 | 0 |
| 실제 창·포커스·확인창 테스트 | 6 | 0 |
| 합계 | 306 | 0 |

기존 보드·블록 및 엔진 클래스별 JaCoCo 기준 검사도 통과했다.
추가 검증은 다음 동작을 다룬다.

- 다섯 모드 각각의 패턴 켬/끔 저장, 이전 설정 파일 이행, 손상된 설정 복구.
- 일곱 블록의 회전 전후·고정 후·다음 미리보기 렌더링 일치.
- 작은 칸에서도 일곱 패턴의 이미지가 서로 다름, 속이 빈 고스트와 엔진 상태 보존.
- 설정 화면의 모드별 패턴 기본값, 사용자의 독립 선택 보존.
- 크기 선택·기본값 복구에서 유지·취소·저장 실패와 다른 편집값 보존.
- 실제 창에서 확인창이 열리기 전 크기 적용, 유지·취소·닫기·Esc·시간 초과 복원.

시간 초과 검사는 동일한 확인창을 1초로 설정해 실행하며, 기본 확인창의 15초 안내도 검사한다.
창 검사는 Swing 이벤트를 통해 실행한다. OS 입력을 외부에서 주입하지 않는다.
큰 프리셋은 운영체제가 화면의 작업 영역에 맞춰 제한할 수 있으므로 실제 창 검사에는 작은 프리셋을 사용했다.
큰 프리셋의 제안·저장·복원은 화면 없는 테스트에서 검사했다.

실제 창에서 생성한 다섯 모드 설정 화면과 확인창 이미지를 확인해 글자 대비와 작은 창의 미리보기 배치도 점검했다.
보고서는 `build/reports/tests/`와 `build/reports/jacoco/test/html/index.html`에 생성된다.
확인 이미지는 `build/review-settings-*.png`, `build/review-window-confirm.png`에 생성된다.

이번 후속 변경은 로컬 구현·검증 범위다. 사용자 요청에 따라 원격 push와 PR #14 수정은 하지 않았다.
Windows·Ubuntu의 이번 변경에 대한 원격 CI 결과는 아직 없다.
