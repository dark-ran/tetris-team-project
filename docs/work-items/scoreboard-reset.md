# 스코어보드 초기화 제어

작업 브랜치: `integration/pr-7-8-11`.
검증일: 2026-10-08.

게임오버 이름 입력 수정 커밋 `a900000` 이후 별도 변경으로 구현했다.

## 연결 규칙

- `AppController.resetScoreboard()`는 영구 기록·메모리 랭킹·화면을 함께 초기화한다. 성공은 `true`, 실패 또는 앱 종료 상태는 `false`다. Swing EDT에서 호출한다.
- 기존 `resetScores()`는 새 메서드를 호출하는 호환용 진입점으로 유지한다.
- `ScoreboardScreen.clearRecords()`는 테이블의 기록·선택·메시지만 초기화하는 화면 메서드다.
- 스코어보드와 설정의 **기록 초기화** 버튼은 앱의 초기화 메서드에 연결한다.
- 저장소의 기존 `ScoreBoardService.reset()`·`ScoreRepository.clear()`를 사용한다. 별도 파일 삭제 경로를 만들지 않는다.

## 동작

초기화 전에 저장 대기 중인 게임 기록이 있으면 먼저 저장을 재시도한다.
재시도가 실패하면 초기화를 중단해 대기 중인 이름·점수를 보존한다.

파일 초기화에 성공한 뒤에만 메모리와 테이블을 비우고, 최고 점수를 0으로 바꾸며 최근 등록 강조를 해제한다.
파일을 다시 읽어도 기록이 비어 있고, 손상된 파일에서 발생했던 읽기 경고도 해제된다.
같은 초기화를 반복 호출할 수 있다.

파일 초기화 실패 시 기존 파일·메모리 랭킹·테이블의 기록과 선택·최근 등록 정보를 유지한다.
설정 또는 스코어보드 화면에 오류를 표시하고 완료로 표시하지 않는다.
초기화 성공·실패는 현재 화면을 유지하며, 설정·게임 진행 상태를 변경하지 않는다.
앱이 종료된 뒤에는 초기화를 실행하지 않는다.

실제 사용자 기록을 대상으로 한 초기화는 수행하지 않았다. 모든 검증 데이터는 테스트 전용 임시 폴더에 저장했다.
