# 황금 블록

## 구현 계획

1. 일반 블록 7종의 모양·이동·회전을 유지하고 네 칸 모두에 황금색과 G를 표시한다.
2. 보드에 칸별 아이템 정보를 저장하여 고정·줄 이동·상태 사본에서도 황금 속성을 보존한다.
3. 삭제할 줄에 황금 칸이 있으면 그 줄 삭제 처리의 점수를 5배 적용한다. 낙하 점수와 누적 줄 수에는 배율을 적용하지 않는다.
4. 10줄 보상과 미리보기에 연결하고 기존 아이템과의 상호작용을 검증한다.
5. 별도 기능 커밋으로 정리하고 macOS 실행 앱을 빌드한다.

## 등장·표시·이동

- 아이템 모드에서 누적 10줄 삭제마다 L·무게추 W·폭탄 B·황금 G·[1칸 블록 1](single-item.md) 중 하나를 각각 20% 확률로 지급한다.
- 일반 모드에는 등장하지 않는다. 일반 블록 7종의 생성 목록과 확률은 유지한다.
- 일반 블록 7종 중 다음에 추가될 블록의 모양을 사용한다. 모든 칸에 황금색과 G를 표시한다.
- 새로 추가되는 미리보기에 표시하고 그 블록을 그대로 생성한다. 이미 미리 본 블록은 바꾸지 않는다.
- 기존 자동 낙하·좌우 이동·회전·즉시 낙하를 사용한다.
- 고정된 뒤에도 황금색과 G를 유지한다. 줄 삭제로 내려온 칸도 황금 속성을 유지한다.

## 삭제와 점수

- 한 번에 삭제하는 줄 중 황금 칸이 하나라도 있으면 해당 처리의 줄 삭제 점수를 5배 적용한다.
- 예: 두 줄을 함께 삭제하면서 황금 칸이 포함되면 300×5 = 1,500점이다.
- 여러 황금 칸이나 여러 황금 블록이 함께 삭제되어도 배율은 한 번만 적용한다.
- 삭제하지 않는 다른 줄의 황금 칸은 배율에 포함하지 않는다.
- 황금 블록 자체의 고정뿐 아니라 다른 일반 블록이 나중에 그 줄을 완성해도 적용한다.
- L 아이템이 황금 칸이 있는 줄을 삭제할 때도 적용한다. 빈칸이 있는 줄도 같은 규칙이다.
- 폭탄·무게추가 개별 황금 칸을 지우는 경우는 0점이다. 지운 칸의 아이템 정보도 제거한다.
- 낙하 점수는 기본 규칙을 사용한다. 실제 삭제한 줄 수만 누적하며 10줄 보상 조건을 5배로 계산하지 않는다.

## 공통 구조

- `ItemType`: 전체 칸 표시 여부와 줄 삭제 배율을 보관한다.
- `Board`: 기존 칸 값 0~7과 별도로 칸별 아이템 정보를 보관한다. 고정·삭제·줄 이동·초기화·복사에서 함께 처리한다.
- `LineClearBonus`: 삭제 전 해당 줄의 아이템 배율을 확인하고 가장 높은 배율을 한 번 선택한다.
- `GameActionResult.lineScoreMultiplier()`: 이번 줄 삭제의 배율을 전달한다. 기존 생성자는 기본값 1을 사용한다.
- `ScoreSystem`: 줄 삭제 점수에만 배율을 적용한다. 엔진에는 황금 아이템을 직접 검사하는 분기를 추가하지 않는다.
- 화면은 같은 아이템 표시 함수로 현재 블록·미리보기·고정 칸을 그린다.

## 검증

`./gradlew build jacocoTestReport`로 아래 내용을 검사한다.

- 7종 모양과 네 방향 회전의 G 유지
- 고정·보드 사본·줄 이동·재시작에서 아이템 정보 보존 또는 초기화
- 뒤에 생성된 일반 블록의 줄 완성, 복수 줄·복수 황금 블록, 부분 삭제 후 남은 황금 칸의 재사용
- 삭제 대상이 아닌 황금 칸 제외, L의 줄 삭제, 폭탄·무게추의 개별 칸 삭제
- 낙하 점수와 배율 분리, 실제 누적 줄 수와 10줄 보상 유지
- 실제 10줄 보상 → 미리보기 → 생성 → 고정 → 다음 블록의 줄 삭제·점수 연결
- 색각 모드 5종의 미리보기·낙하·회전·고정된 황금 칸 표시
- 아이템 100,000회 생성 시 네 종류 각각 기대 횟수 25,000회 대비 오차 ±5% 이내

2026-10-26 macOS arm64 검증: 단위 테스트 489개와 통합 테스트 1개 통과, 전체 줄 커버리지 93.68%.
100,000회 생성 결과는 L 25,051개·W 24,990개·B 24,887개·G 25,072개이며 모두 허용 오차 이내이다.
macOS 앱 빌드, 화면 크기 3종의 표시 검증, 성능 검사 6건을 통과하였다.
