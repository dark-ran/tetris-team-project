# 폭탄 아이템

추가 아이템 중 폭탄을 구현하였다. 팀에서 제안한 '고정 시 5×5 삭제, 점수 0점'을 기준으로 아래 규칙을 적용한다.

## 등장과 표시

- 아이템 모드에서 누적 10줄 삭제마다 지급하는 아이템에 폭탄을 포함한다.
- L·무게추 W·폭탄 B·[황금 G](golden-item.md)를 각각 25% 확률로 선택한다. 일반 모드에서는 등장하지 않는다.
- 폭탄은 가로 3칸의 다이너마이트 모양이며 가운데 칸에 `B`를 표시한다. 일반 블록 7종의 생성 목록에는 추가하지 않는다.
- 새로 추가되는 미리보기에 표시하고, 표시된 폭탄을 그대로 생성한다. 이미 미리 본 블록은 바꾸지 않는다.

## 이동·폭발·점수

- 기존 자동 낙하와 좌우 이동을 사용하며 가로 모양을 유지한다. 회전하지 않는다.
- 세 칸 중 어느 칸이든 아래가 막히면 더 내려가지 않는다. 가운데가 닿을 때까지 양끝을 관통시키지 않는다.
- 바닥이나 고정 블록을 만나 더 내려갈 수 없을 때, 다음 낙하 처리에서 폭발한다. 즉시 낙하는 한 번에 처리한다.
- 고정할 때 바로 아래의 접촉 상태로 폭발 중심을 결정한다. 가운데가 닿으면 가운데, 한쪽 끝만 닿으면 그 끝을 선택한다. 양끝이 동시에 닿고 가운데는 비어 있으면 가운데를 선택한다. 바닥에서도 가운데를 선택한다.
- 중심은 폭탄 자체의 칸이다. 중심에서 위·아래·왼쪽·오른쪽 각각 2칸까지, 최대 5×5 영역의 고정 칸을 삭제한다.
- 착지 예상 위치에서 폭발 중심을 노란 실선으로 표시한다. 좌우 이동 시 다시 계산하며, 이미 착지한 상태에서도 표시한다.
- 보드 밖의 영역은 제외한다. 범위 밖의 블록은 이동하지 않으며, 빈칸을 채우기 위해 위쪽 블록을 내리지 않는다.
- 폭탄 자체는 고정 칸으로 남지 않는다. 낙하 점수와 폭발 점수는 모두 0점이다.
- 삭제한 개별 칸은 누적 삭제 줄 수와 다음 아이템 지급 조건에 포함하지 않는다.
- 착지 예상 위치 조회·일시정지·좌우 이동만으로는 폭발하지 않는다.

## 연결과 검증

`PieceRules`에 이동·고정 효과·점수·소멸 규칙을 등록한다.
`BombEffect.onLock()`이 `Board.removeArea()`를 호출한다. 엔진에는 폭탄 종류를 검사하는 분기를 추가하지 않는다.
다른 영역 효과도 `LockEffect.onLock()`을 구현하여 연결할 수 있다.
`LockEffect.targetCell()`은 효과의 중심을 조회하며, 화면은 같은 규칙으로 중심을 표시한다.
`BombMovement`는 회전을 제한하고 세 칸 전체의 충돌을 검사한다.

`./gradlew build jacocoTestReport`로 아래 내용을 검사한다.

- 10줄 보상 → 미리보기 → 실제 생성 → 폭발 연결, 일반 모드 제외, 재시작 초기화
- 자동 낙하·아래 키·즉시 낙하의 동일한 폭발 결과
- 중앙·네 모서리·가장자리의 범위 제한, 범위 밖 보존, 중복 폭발 방지
- 아래쪽 접촉 조합 7종의 중심 선택, 양끝 겹침 방지, 이동 후 중심 재계산
- 착지 예상 위치와 실제 고정 위치의 중심 표시, 조회·그리기 중 보드 보존
- 점수·누적 줄 수 제외와 다음 일반 블록의 점수 계산 재개
- 색각 모드 5종의 보드·미리보기 B 표시
- 아이템 100,000회 생성 시 종류별 기대 횟수 대비 오차 ±5% 이내

폭탄 형태 변경 시점의 검증(2026-10-26 macOS arm64): 단위 테스트 447개와 통합 테스트 1개 통과, 전체 줄 커버리지 93.55%.
황금 블록 추가 후 전체 검증 결과는 [G 아이템 문서](golden-item.md)에서 확인한다.
macOS 앱 빌드와 화면 크기 3종의 표시 검증을 완료하였다.
