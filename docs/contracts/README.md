# 모듈 연결 안내

다른 파트의 코드를 연결하거나 기능을 확장할 때 확인하는 문서 모음이다. 각 문서는 클래스의 역할,
메서드의 입력·반환값, 상태 변경 규칙과 사용 예시를 설명한다.

## 어디부터 읽으면 좋을까?

| 작업 | 먼저 읽을 문서 | 확인할 내용 |
|---|---|---|
| 게임 시작과 행동 전달 | [게임 엔진 연결](game-engine.md) | `newGame()`, `apply()`, 상태 전환 |
| 점수·속도·랭킹 연결 | [게임 엔진 연결](game-engine.md) | 행동 결과, 누적 수치, 최종 점수 반영 순서 |
| 보드와 블록 그리기 | [보드와 블록](board-and-piece.md) | 칸 저장값, 내부 좌표와 보드 좌표, 사본 |
| 시작 위치와 다음 블록 개수 변경 | [게임 엔진의 확장 예시](game-engine.md#8-기능을-확장하는-방법) | 시작 위치 규칙 교체, 목록 생성자 전달 |
| 구현 범위와 검증 결과 확인 | [작업 기록](../work-items/README.md) | 완료 기준, 테스트 결과, 후속 작업 |

## 파트 사이의 책임

| 파트 | 역할 | 연결할 내용 |
|---|---|---|
| 1번 | 게임 핵심 로직 | 보드·블록·게임 상태를 변경하고 처리 결과 제공 |
| 2번 | 실행·입력·게임 루프·설정 | 키를 행동으로 변환하고 자동 낙하 시점 발생 |
| 3번 | 앱 제어·점수·속도·랭킹 | 전체 호출 순서, 점수·속도 계산, 화면 전환과 후처리 |
| 4번 | Swing 화면 | 게임 상태 표시와 화면 입력 전달 |

문서의 연결 규칙은 3번 파트가 모듈 통합 과정에서 관리한다. 연결 규칙에 영향을 주는 구현 변경은
해당 파트의 코드·테스트와 문서를 함께 수정한다.

## 분배 기준과 현재 구현

1번 파트의 파일과 담당 기능을 기준으로 확인한 결과이다.

| 담당 기능 | 구현 위치 | 상태 |
|---|---|---|
| 블록 생성과 다음 블록 관리 | `PieceQueue`, `GameEngine.spawnNextPiece()` | 구현 |
| 블록 종류에 대응하는 보드 값 | `PieceType.cellValue()`, `Board.lock()` | 구현 |
| 블록 형태와 시계방향 회전 | `Tetromino`, `GameEngine.rotateClockwise()` | 구현 |
| 좌우 이동·하강·즉시 낙하 | `GameEngine` | 구현 |
| 보드 경계와 고정된 블록 충돌 | `Board.canPlace()` | 구현 |
| 블록 고정과 완성된 줄 삭제 | `Board.lock()`, `Board.clearFullRows()` | 구현 |
| 새 블록 생성 실패에 따른 게임오버 | `GameEngine.spawnNextPiece()` | 구현 |
| 일시정지·재개와 진행 상태 | `GamePhase`, `GameEngine.apply()` | 구현 |
| 게임 상태 조회와 행동 처리 | `GameState`, `GameAction`, `GameActionResult` | 구현 |

`GameActionResult`와 시작 위치 규칙 두 클래스는 위 기능의 연결·확장을 위한 보조 타입이다.
보드 값은 빈 칸 0과 종류별 1~7이며, 실제 색상과 무늬는 4번 파트에서 정한다.

2·3·4번 파트의 실제 입력·루프·점수 계산·화면 상태 표시 연결은 남아 있다.
현재 `AppController.startGame()`은 화면을 전환하고, `GameScreen.render()`는 아직 미구현이다.
임시 블록 선택과 직접 이동 기능은 게임 화면에서 제거되어 있다.
