# 중간평가 통합 검증

검증일: 2026-10-27. 기능 기준은 main `3ccf291`이다. 로컬 검사는 이 병합과 코드 트리가 같은 `83a5c48`에서 실행했다. 문서·이미지 변경은 게임 동작에 영향을 주지 않는다.

JaCoCo는 단위 테스트 실행을 기준으로 직접 작성한 전체 main 코드(UI·Main 포함)를 측정한다. 별도 창·성능 검사의 실행 데이터로 수치를 부풀리지 않는다. 전체 줄 50% 이상과 기존 핵심 클래스별 70% 검사를 모두 통과했다.

상세 HTML은 `build/reports/tests/`, 커버리지는 `build/reports/jacoco/test/html/index.html`에 생성한다. 요약 원본은 [검증 데이터](verification-results.json)에 보관한다.

## 확률 검사

실제 게임에서 사용하는 PieceQueue를 난이도마다 100,000회 실행했다. 상대오차는 `|실제 횟수 - 기대 횟수| ÷ 기대 횟수 × 100`이며 모든 기본 블록에 5% 이하를 적용한다.

| 난이도 | I 기대 횟수 | I 실제 횟수 | I 상대오차 | 7종 중 최대 상대오차 |
|---|---:|---:|---:|---:|
| EASY | 16,666.67 | 16,895 | 1.37% | 1.37% |
| NORMAL | 14,285.71 | 14,293 | 0.051% | 1.013% |
| HARD | 11,764.71 | 11,814 | 0.419% | 0.7472% |

1,000회 보조 검사는 실제 확률과 기대 확률의 차이 5%p 이내를 확인한다. 5%p와 상대오차 5%는 다른 기준이므로, 요구 범위의 최종 판정에는 표본을 늘린 상대오차 검사를 사용한다. 고정 seed와 추첨 구간 전수 검사로 결과를 재현한다.

ItemGenerator도 100,000회 실행했다. 각 기대 횟수는 20,000회다.

| 아이템 | L | W | B | G | 1 |
|---|---:|---:|---:|---:|---:|
| 실제 횟수 | 20,207 | 19,966 | 20,099 | 19,972 | 19,756 |
| 상대오차 | 1.035% | 0.17% | 0.495% | 0.14% | 1.22% |

L의 부착 위치는 아이템 종류 선택과 별도로 네 칸 중 하나를 추첨한다. 10줄 보상·미리보기·실제 생성·발동·점수·재시작은 각 아이템 연결 테스트로 확인한다.

## 성능 검사

창 크기 3종 × 일반·단색 표시를 조합하여 총 6건을 실행했다. 각 조합에서 준비 50회 후 입력 → 상태 조회 → 화면 그리기를 300회 측정했다. JVM 힙 상한은 256MiB다.

- 처리 시간 p95: 0.557~0.811ms. 최단 자동 낙하 간격 100ms 이내.
- 측정 시 사용 힙: 29.12~54.15MiB.
- 반복 처리 전후 게임 화면 컴포넌트 수: 63개로 유지.

이 측정은 현재 Mac에서의 처리 여유와 컴포넌트 누적 여부를 확인한다. 1.2GHz·물리 RAM 1GB 기기를 그대로 재현한 검사는 아니다.
